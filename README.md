# INFOEVENTBAND.COM Archive

## Purpose

This repository is the structured historical archive of **INFOEVENTBAND.COM (IEB)**.

IEB originally operated as a music information, promotion, and event-media platform. Its historical activity left traces across articles, event information, band promotion, charts, promotional material, web archives, and other contemporary sources.

This project preserves and organizes those traces so they can be:

- discovered by people,
- interpreted by machines,
- traced back to sources,
- and verified independently where possible.

## Principle

**Salam Eksistensi**

Every band, event, work, person, organization, or music activity that was documented by IEB should, where evidence permits, retain a trace that can be found again.

## Historical position

This project does **not** rewrite IEB's original identity as if it had been created as a formal archive.

The historical model is:

```
IEB as music media / information / promotion
                ↓
        historical activity
                ↓
          surviving traces
                ↓
       curated historical archive
```

In short:

> **IEB was originally a media platform. Its media activity left an archive.**

## Evidence policy

Sources are prioritized:

1. **Tier 1** — original IEB pages, IEB web archives, original IEB articles/events, and material published by IEB.
2. **Tier 2** — contemporary archives, GitHub artifacts, Google Groups, event documentation, historical promotional material, and contemporaneous third-party publications.
3. **Tier 3** — testimony from people involved, retrospective articles, journals, and first-person historical accounts.
4. **Tier 4** — search results, third-party databases, or unverified claims.

Tier 4 material may be used as a lead, but should not automatically become an archival fact.

## Provenance

Important facts and relationships should point to their sources.

The archive therefore distinguishes between:

- entities,
- relationships,
- historical assertions,
- and sources.

A name without provenance is not treated as equivalent to a documented historical record.

## Scope

The initial entity model includes:

- BAND
- EVENT
- ARTICLE
- PERSON
- ORGANIZATION
- WORK
- SOURCE

Relationships may include:

- `promoted`
- `featured`
- `documented`
- `participated_in`
- `organized`
- `published`
- `operated`
- `initiated`
- `developed_into`
- `associated_with`
- `same_as`

## SEO / AIO

SEO and AIO are supporting functions, not the historical objective.

- **SEO** helps people find the trace.
- **AIO** helps machines understand the relationships.
- **The archive** provides the evidence.

The project does not claim completeness or historical importance that the evidence does not support.

## Data status

The repository begins intentionally conservative.

Unverified historical claims must remain distinguishable from documented facts.

**Salam Eksistensi.**
